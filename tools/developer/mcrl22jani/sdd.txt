SDD for the pCRL2 -> Automaton translation

Note: 
  tree node attributes like `P.state` are to be stored in a common objectdata class, similar to the one the linearisation code uses.

  effects like the ones regarding variable tables and the like refer to undefined functions/methods. this is just an approximate model for how to translate

As a first approximation, this version doesn't consider data at all, so no process functions / families or instances. Also no actions with data, only actions and their synchronization. And no choice quantification. There's also no conditional operator since there is no data to make predicates about.

We'll later deal with actions with data and their synchronization when one sends (e.g "a(n)") and one receives (e.g "sum b:Nat b(n)")

The first objective is to get the locations and edges as close to what the final product should be.

global variables across the traversal, which is performed DFS pre-order:

stateStack (queue keeping track of the states generated during traversal)


The language to be considered now is:

p ::= a | delta | p1 + p2 | p1 . p2

where a is any action
